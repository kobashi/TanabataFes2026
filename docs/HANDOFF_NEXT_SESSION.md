# 次セッション引き継ぎメモ

対象リリース: `1.6.3`

## 現状

- 管理画面はサーバ共有の本設定、月メニューは投影端末ごとの現場微調整として整理済み。
- 管理画面と月メニューで調整できる項目の比較は `docs/OPERATIONS.md` の「管理画面と月メニューの調整項目比較」を参照。
- 月メニューは起動時に `body` 直下へ移動し、投影ステージ外の独立DOMとして扱う。全画面表示は `document.documentElement` を対象にする。
- 月メニュー表示中は、3Dボックス更新を止め、星空/天の川/流星Canvasを一時停止し、見える部分の少ない短冊描画を省略する。閉じたら復帰する。
- 月メニューのローカル調整は、操作した項目だけサーバ設定より優先する。保存値クリアでサーバ設定追従へ戻る。
- 視差3Dの焦点距離は `projectionParallaxViewerDistance` と一致する。実カメラ系モードの遠近スケールは壁面へ落ちる影の倍率を使い、`mapping` モードのピンホール倍率と揃えてある。
- 実カメラの向きは `projectionParallaxCameraOrientationMode` で `target`（注視点ロック、既定）と `parallel`（壁面に平行）から選ぶ。`parallel` ではカメラ注視点X/Yを使わない。
- 実カメラの人力同期用に `projectionParallaxCameraDelaySeconds`（`0.0〜1.0` 秒、既定 `0.5`）がある。笹舟が先に動き、この時間の後に仮想カメラが動き始める。
- 月メニューに「短冊の高さを揃える」がある。X位置とz順は変えず、配置Yを現在値の中央値へ揃えて `localStorage` に保存する。
- `npm run dev` は `data/proxy-state.json` ではなく3001/3002の実際の使用状況から起動先を選ぶ。両方使用中なら既存プロセスを止めずエラー終了する。

## 重要な設計判断

- 短冊配置のサーバ保存は採用していない。短冊配置は投影端末ブラウザの `localStorage`。
- 3Dボックス位置とカメラ注視点は、管理キーが同じブラウザに保存されている場合のみ月メニュー操作からサーバへも保存する。
- 短冊奥行は画面上Y位置を使わず、z順だけから作る。
- 月メニューの描画安定化は、z-indexだけでなく、独立DOM化、背景描画停止、3Dボックス更新停止、Canvas停止の複合対策で行っている。
- 見える部分の少ない短冊の描画省略は通常時には体感効果が薄かったため、月メニュー表示中だけ有効。
- **視差の評価は壁面上の絵ではなく、実カメラが撮った映像で行う。** 壁面上の絵だけを見ると投影面上の点は動かないV字応答に見えるが、実カメラの移動分で打ち消され、合成後は `-1/(z+D)` の単調な応答になる。壁面上の絵を根拠に注視点固定を外して純平行移動へ変えてはいけない。
- 壁面からの距離を変えても、仮想カメラの移動振幅と短冊のワールド奥行きは変えない。振幅の較正は `projectionParallaxStrength` だけで行う。

## 次回候補

- Android実機で月メニューのチラつきが残るか確認する。残る場合は、月メニューをさらに軽量な不透明背景にし、半透明/影/スクロール領域の描画負荷を減らす。
- 管理画面の雲スライダーと短冊目標スライダーが広い画面でグループからはみ出る問題を確認し、グリッドの最小幅と折り返しを調整する。
- OSC経由で演出ON、プリセット1〜3読み込み、笹舟OSCモードを操作する案が未実装。
- 表示短冊数が多い時の処理落ちは、通常時の短冊軽量モードよりも、視差更新fps間引き、影/フィルタ削減、入替中の深度更新固定のほうが効果が出る可能性が高い。
- `projectionParallaxViewerDistance` を既定値 `2.5` から変えている環境は、1.6.3 で見た目が変わる。現場での再較正が必要かどうかを実機で確認する。
- カメラ遅延は現状「笹舟が先、仮想カメラが後」の固定順。実カメラ操作者の反応時間に合わせて現場で詰める。
